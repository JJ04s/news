# 뉴스스탠드 개발 규정 (Gemini CLI 가이드라인)

이 문서는 '뉴스스탠드' 프로젝트를 수행할 때 Gemini CLI가 반드시 준수해야 하는 **최우선 지침**입니다.

## 1. 정보 참조 우선순위
작업 중 의문이 생기거나 세부 구현 방식 결정이 필요할 경우 다음 순서를 따릅니다.
1. **본 파일 (`.gemini/GEMINI.md`)**: 프로젝트의 핵심 원칙 및 제약 사항
2. **PDF 문서 (`gemini/` 폴더 내)**: 
   - `design-system.pdf`: 상세 디자인 토큰 및 컴포넌트 스펙
   - `ui-spec.pdf`: 전체 화면 레이아웃 및 뷰 전환 명세
3. **에이전트 재량**: 위 문서들에 명시되지 않은 기술적 세부 구현은 최신 React 생태계 관례에 따라 자율적으로 판단하여 진행합니다.

## 2. 프로젝트 개괄 (Project Overview)
이 프로젝트는 데스크톱 중심의 한국어 뉴스 포털인 '뉴스스탠드'의 Web UI/UX를 구현하는 과제입니다. 사용자는 6x4 그리드 형태의 전체 언론사를 탐색하고, 원하는 언론사를 구독/해지할 수 있으며, 개별 언론사의 기사 리스트 뷰에서 타이머에 의한 자동 전환 기능을 경험합니다. 

## 3. 수행 방법 및 기술 스택 (Execution Methodology)
- **프레임워크**: React (Functional Components, Hooks 기반)
- **상태 관리**: React 내장 상태(Context API 등)를 기본으로 하되, 복잡도에 따라 외부 라이브러리(Zustand, Jotai 등) 사용 허용
- **스타일링**: CSS Modules 또는 SCSS 등 컴포넌트 스코프 스타일링 방식 권장 (PDF의 디자인 토큰을 쉽게 변수화할 수 있는 도구 사용 허용)
- **애니메이션 및 아이콘**: 복잡한 타이밍 로직과 시각적 효과 구현을 위해 Framer Motion, 외부 아이콘 라이브러리(Lucide-react 등)와 같은 **외부 라이브러리 사용을 적극 허용**하며, 생산성을 높이는 방향으로 구현합니다.

## 4. 주석 작성 가이드라인 (Commenting Guidelines for Learning)
사용자의 학습을 돕기 위해 코드를 작성할 때 다음 규칙을 엄격히 준수합니다.
- **기능 단위 주석**: 모든 코드 라인이 아닌, 하나의 독립적인 기능을 수행하는 블록(함수, 로직 덩어리) 단위로 주석을 작성합니다.
- **설계 포인트 및 사유 명시**: 구현 시 재량이 발휘된 부분에는 **어떤 설계 선택을 했는지(What)**와 **왜 그렇게 설계했는지(Why)**를 상세히 설명합니다.
- **종료 포인트 명시**: 특정 기능의 구현이 끝나는 지점에 주석으로 명확히 종료되었음을 알립니다 (예: `// --- [기능명] 구현 종료 ---`).
- **친절한 설명**: 사용자가 이해하기 쉬운 JS 기반의 용어를 사용하며, 로직의 흐름을 논리적으로 설명합니다.

## 5. 핵심 디자인 및 로직 명세 요약 (PDF Summary)
- **레이아웃 및 타이포그래피**: 고정 1280x720 캔버스 내 930px 중앙 정렬. 국문은 Pretendard, 숫자는 IBM Plex Mono, 세리프 로고는 Noto Serif KR을 기본으로 합니다.
- **색상 규칙**: 강조색(`#7890E7`)은 오직 '구독 수 뱃지'와 '활성화된 프로그레스 탭'에만 제한적으로 사용합니다. 모든 구분선은 1px의 `#D2DAE0`을 사용합니다.
- **오토 롤링 티커 (Header)**: 3.2초 주기로 아이템이 전환되며, 0.55초의 Crossfade(cubic-bezier 애니메이션) 효과가 적용된 2개의 독립된 레인을 구현해야 합니다.
- **리스트 뷰 프로그레스 (Category Tab)**: 6초 주기로 진행되는 Linear 프로그레스 바를 구현하며, 100% 도달 시 다음 기사 및 언론사로 자동 전환되어야 합니다.
- **상호작용 및 접근성**: `Hover` 시 구독/해지 버튼 노출, 키보드 네비게이션 지원, `prefers-reduced-motion` 환경 대응을 필수로 고려합니다.
